## 第 2 步：KITTI

### 采集车和规模（课件第 13、16 页）

一辆大众帕萨特，车顶装了：2 个彩色 + 2 个灰度相机（两两组成双目），1 个 64 线激光雷达（Velodyne HDL-64E，离地 1.73 米），GPS/IMU。相机离地约 1.65 米。3D 检测部分：7481 张训练、7518 张测试，共 80256 个标注对象，评测车、行人、骑车人三类。

### 标定文件 calib/000000.txt：三把钥匙

| 名字 | 形状 | 干什么 |
| --- | --- | --- |
| `Tr_velo_to_cam` | 3 × 4 | 激光雷达坐标 → 相机 0 坐标（外参，就是 L02 的 T） |
| `R0_rect` | 3 × 3 | 相机 0 → “校正后”的相机 0（双目校正，把几个相机摆正对齐，转得很少） |
| `P2` | 3 × 4 | 校正后的相机坐标 → 左彩色相机（2 号）的像素：内参 K 再加一点平移 |

课件第 16 页的公式 **y = P2 · R0_rect · Tr_velo_to_cam · x** 就是 L02 那条链：激光雷达点 → 相机 → 像素。从右往左读。

P2 里的数（000000 帧）：f = 721.54，cx = 609.56，cy = 172.85，第 4 列 (44.86, 0.22, 0.003) 是 2 号相机相对 0 号相机的位置乘上 f（双目基线），所以 P2 是 3 × 4，不是 3 × 3。

### 标注文件 label_2/000000.txt：一行 15 个数（课件第 17、18 页）

```text
Pedestrian 0.00 0 -0.20 712.40 143.00 810.73 307.92 1.89 0.48 1.20 1.84 1.47 8.41 0.01
```

| 位置 | 字段 | 这一行的值 | 含义 |
| --- | --- | --- | --- |
| 1 | type | Pedestrian | 类别；DontCare 表示这块区域不参与评测 |
| 2 | truncated | 0.00 | 被照片边缘截掉多少（0 到 1） |
| 3 | occluded | 0 | 遮挡：0 完全可见、1 部分遮挡、2 大部分遮挡、3 不知道 |
| 4 | alpha | −0.20 | 观察角（弧度），见下面 |
| 5–8 | 2D 框 | 712.40 143.00 810.73 307.92 | 左、上、右、下（像素） |
| 9–11 | 尺寸 | 1.89 0.48 1.20 | **高、宽、长**（米），注意顺序 |
| 12–14 | location | 1.84 1.47 8.41 | 相机坐标系（x 右 y 下 z 前）里的**底面中心** |
| 15 | rotation_y | 0.01 | 绕相机 y 轴（向下）的朝向（弧度） |

几个容易错的地方：

1. **location 是底面中心**，不是正中心。很多博客写成“中心”。实验会把两种理解都投影一遍，和人工标的 2D 框比，一看就知道。
2. **rotation_y 的方向**：0 = 车头朝右（相机 x 方向），−π/2 = 车头朝前（和你同向），+π/2 = 朝你开过来。课件第 17 页那辆 Truck 是 −1.56（同向前行），Car 是 1.57（对向来车）。
3. **alpha 和 rotation_y 的关系**：alpha = rotation_y − atan2(x, z)。atan2(x, z) 是“从相机看过去，物体在哪个方向”。同一辆车停在你正前方和斜前方，rotation_y 一样，但照片里看到的是不同的面。alpha 描述的就是“看到哪一面”，单目 3D 检测常用它当学习目标。这一行：0.01 − atan2(1.84, 8.41) = −0.205，标注写 −0.20，对得上。
4. **2D 框和 3D 框是分开标的**：3D 框投影出来的外接框，和人工在照片上画的 2D 框差 6 到 20 像素是正常的。

## 第 3 步：nuScenes

### 规模和传感器（课件第 19、20 页）

1000 个场景、每个 20 秒；6 个相机、1 个 32 线激光雷达、5 个毫米波雷达，加 GPS/IMU。140 万张图像、39 万帧激光雷达、140 万个标注框，23 类。

**关键帧和中间帧（第 21 页）**：只有每秒 2 帧的关键帧有标注，在 `samples/`；相机其实每秒 12 帧、激光雷达每秒 20 帧，没标注的放在 `sweeps/`。时序方法（BEVDet4D、BEVFormer）会用到前几帧。

### 13 张表，用 token 连起来（第 22 页）

像数据库：每条记录有一个 `token`（唯一编号），表之间用 token 互相引用。画框最常用的 4 张：

| 表 | 存什么 | 换成矩阵是 |
| --- | --- | --- |
| `sample_annotation` | 一个框：中心 translation、尺寸 size（**宽、长、高**）、朝向 rotation（四元数），**在世界坐标系里** | — |
| `ego_pose` | 某个时刻车在世界里的位置和朝向 | T_global_from_ego |
| `calibrated_sensor` | 某个传感器在车上的位置和朝向，相机还有内参 `camera_intrinsic` | T_ego_from_cam、K |
| `sample_data` | 一张照片 / 一帧点云：文件名、时间戳，指向它的 ego_pose 和 calibrated_sensor | — |

框存在世界坐标系里，是因为一个物体在多帧之间要用同一个 `instance` 跟踪，世界坐标系不随车动。

把框画到照片上，要走三步：

```text
世界坐标 ──inv(T_global_from_ego)──▶ 车坐标 ──inv(T_ego_from_cam)──▶ 相机坐标 ──K──▶ 像素
```

**容易错的一点**：每张照片、每帧点云都有自己的 `ego_pose`（拍摄时刻不同，车已经往前开了）。要精确画到某张照片上，用的是这张照片的 `sample_data` 指向的那个 ego_pose，不是激光雷达那帧的。车速 10 m/s 时，两者差 0.05 秒就是 0.5 米。

### 四元数：nuScenes 存旋转的方式

绕单位轴 n 转 θ 角，写成 (cos θ/2, sin θ/2 · n)，顺序是 (w, x, y, z)。例子：绕 z 轴（向上）转 90° = (0.7071, 0, 0, 0.7071)。前视相机的标定旋转大约是 (0.5, −0.5, 0.5, −0.5)，换成矩阵正好是 L02 的 `R_EGO_FROM_CAMAXES`（换轴：相机 z 朝车前方）。转换函数 `quat_to_rot` 在 `bev/pose.py`，助手写好了。

### KITTI 和 nuScenes 对照（面试常问）

| | KITTI | nuScenes |
| --- | --- | --- |
| 标注框的坐标系 | 相机坐标系（x 右 y 下 z 前） | 世界坐标系 |
| 框的位置 | 底面中心 | 正中心 |
| 尺寸顺序 | 高、宽、长 | 宽、长、高 |
| 朝向 | rotation_y：绕相机 y 轴（向下） | 四元数，实际上是绕 z 轴（向上）的 yaw |
| 相机 | 前向双目（2 彩色 + 2 灰度） | 6 个环视 |
| 时序 | 单帧为主 | 关键帧 2 Hz + 中间帧 |
| 评测 | 3D IoU 的 AP | 中心距离的 mAP + NDS（下一课） |

## 第 4 步：你来敲（`bev/datasets.py`）

1. `parse_kitti_label(line)`：`line.split()` 得到 15 个字符串，和 `KITTI_FIELDS` 配对。`type` 留字符串，`occluded` 转 `int`，其余转 `float`。
2. `kitti_box_corners(h, w, l, x, y, z, ry)`：照文档字符串写出 8 个角在框自己坐标里的 x、y、z（三个长度 8 的列表），拼成 (3, 8)，左乘绕 y 轴的旋转矩阵，转置成 (8, 3)，再加上 (x, y, z)。
3. `global_to_camera(pts_global, ego_pose, calib)`：两个位姿都用 `pose_to_T` 变成矩阵，拼出 `T_cam_from_global = inv(T_ego_from_cam) @ inv(T_global_from_ego)`，交给 L02 的 `transform_points`。

卡住了先看文档字符串，再看 `solutions/datasets_l03.py`。
