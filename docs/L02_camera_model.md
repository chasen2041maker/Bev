## 第 1 步：先预测

nuScenes 那样的车顶上装了 6 个相机（前、左前、右前、左后、右后、后），每个视野大约 77°。

1. 车**左前方 30°**、离车 15 米的一个点，会被几个相机同时拍到？　① 1 个　② 2 个
2. 车头前 **2 米**、0.75 米高的一个点（贴得很近），前视相机拍得到吗？　① 拍得到　② 拍不到

## 第 2 步：齐次坐标——为什么要在点后面补一个 1

把一个点从“车坐标系”换到“相机坐标系”，要做两件事：**转个方向**（旋转 R，3 × 3）、**挪个位置**（平移 t，3 个数）。

```text
p_cam = R · p_ego + t
```

旋转是乘法，平移是加法，两步写起来麻烦，连着换好几个坐标系更麻烦。办法是在点后面补一个 1，把 R 和 t 拼成一个 4 × 4 矩阵 T：

```text
[ p_cam ]   [ R  t ] [ p_ego ]
[   1   ] = [ 0  1 ] [   1   ]
```

乘出来第一行正好是 R·p_ego + t·1。这样“转 + 挪”就成了**一次乘法**，几个坐标系连着换就是几个矩阵连乘。

数字例子：只平移 t = (10, 0, 0)、不旋转，点 (1, 2, 3) → (11, 2, 3)。只往左转 90°，车前方的点 (1, 0, 0) → (0, 1, 0)（跑到左边）。

**命名规矩**（整个项目都这样）：`T_cam_from_ego` 读作“从车到相机”，把车坐标系里的点变到相机坐标系里。连乘时从右往左读：`T_cam_from_world = T_cam_from_ego @ T_ego_from_world`，中间的名字要能“消掉”。

## 第 3 步：外参、内参，和完整的一条链

### 外参 T_cam_from_ego：相机装在车上哪、朝哪

直接写“从车到相机”不好想，先写反过来的 `T_ego_from_cam`（相机在车里的位置和朝向），再求逆。朝向分两步：

1. **换轴**：相机的三根轴在车坐标系里指向哪？

   | 相机的轴 | 指向 | 在车坐标系里 |
   | --- | --- | --- |
   | x | 右 | (0, −1, 0) |
   | y | 下 | (0, 0, −1) |
   | z | 镜头前方 | (1, 0, 0) |

   把这三列排起来就是 `R_EGO_FROM_CAMAXES`（在 `bev/rig.py` 里）。下一课你会看到，nuScenes 前视相机标定文件里的旋转四元数 (0.5, −0.5, 0.5, −0.5)，换成矩阵正好就是它。

2. **转向**：左前相机再绕 z 轴往左转 55°，后视相机转 180°。

`bev/rig.py` 里的 `camera_extrinsics(x, y, z, yaw)` 就是这么写的，助手写好了，你要看懂。

### 内参 K：镜头把相机坐标系里的点画到照片上

```text
    [ f  0  cx ]                        [ u·z ]
K = [ 0  f  cy ]        K · p_cam   =   [ v·z ]    再除以 z 得到 (u, v)
    [ 0  0  1  ]                        [  z  ]
```

就是 L01 那行公式 u = f·x/z + cx 写成矩阵。f 是焦距（像素），cx、cy 是光心。

**课件 009 第 10 页要更正两处**：

1. 那页的矩阵是 `[f 0 0 0; 0 f 0 0; 0 0 1 0]`，**没有 cx、cy**。等于假设光心在照片左上角，正前方的点会落在像素 (0, 0) 附近。实验里会算给你看，偏了整整 (800, 450)。真实相机都有 cx、cy（nuScenes 前视约 816、491）。
2. 右边的向量标成了“世界坐标”，其实是**相机坐标**。世界坐标要先乘外参变到相机坐标，才能乘内参。那页多出来的第 4 列 0，是为了接住齐次坐标里补的那个 1。

### 完整的一条链

```text
像素 (u, v)  ←K←  相机坐标  ←T_cam_from_ego←  车坐标  ←T_ego_from_world←  世界坐标
```

课件 001 第 16 页 KITTI 的公式 y = P · R_rect · T_velo→cam · x 也是这条链，只是名字不同（下一课细讲）。

### 拍不拍得到：有效性

三个条件都满足才算这个相机拍到：深度 > 0（在镜头前面）、0 ≤ u < 宽、0 ≤ v < 高。这个 True/False 后面一直要用：DETR3D 用它决定从哪几个相机取特征，BEVFormer 用它决定哪些相机“命中”这个格子。

### 反过来：像素 → 射线

K 求逆乘 (u, v, 1)，得到相机坐标系里 z = 1 处的一个点。这条射线上的每个点（z = 1、10、50 米……）**都投到同一个像素**。所以只看一张照片，深度是丢掉的。这就是整门课的核心难题，后面分两条路解决：

- **2D → 3D**：先猜每个像素的深度，再“抬”进 3D（第 1 部分 LSS，课件 009 第 9 页）
- **3D → 2D**：反过来，拿 3D 里的点投到照片上去取特征（第 3 部分 DETR3D、BEVFormer，课件 009 第 15 页）

## 第 4 步：你来敲（`bev/camera.py`）

1. `transform_points(T, pts)`：`pts` 是 (N, 3)。用 `np.hstack` 在后面拼一列 1 变成 (N, 4)，算 `(T @ homo.T).T`，取前 3 列。
2. `project_points(K, T_cam_from_ego, pts_ego, width, height)`：先 `transform_points` 变到相机坐标；`depth` 就是第 3 列；`K @ pts_cam.T` 再按第 3 行除；最后按上面三个条件算 `valid`。深度 ≤ 0 时除法会出警告，可以用 `np.errstate(divide="ignore", invalid="ignore")` 包起来。
3. `pixel_to_ray(K, u, v)`：`np.linalg.inv(K) @ np.array([u, v, 1.0])`。

卡住了先看文档字符串，再看 `solutions/camera_l02.py`。
